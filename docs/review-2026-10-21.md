# Wireless 计划生成优化与证据边界（2026-10-21）

本轮基于 `08fe6a6`，检查配置作用域与实体构建、运行字段和完整性、共享采集与 AP 选择、建议及计划导出流程。新增 AGENTS.md 记录模块职责、秘密与资源所有权、计划指纹、报告持久性和验证入口。

多模板报告原先为每个候选计划重新规范化、排序、JSON 序列化并计算整份配置的 SHA256。N 个模板各有一个候选时，重复处理整份配置形成平方级成本。现在只在第一项合格计划时计算指纹，保存在本次 write_review 的局部变量；同设备同次报告复用，下次报告重新计算，不引入实例或全局缓存。计划的命令、回退、来源与顺序不变。

另外确认了可执行计划的证据漏洞：write_review 接收外部 advice 时，原先直接取第一条配置记录，即使观测 partial 或有多份记录也能导出计划。新增测试先复现 partial 导出，再修复为要求 complete 且恰好一个 Hash 配置记录。提供建议不能替代配置证据。诊断与注释化建议仍可保留；apply 的实时回读检查继续独立执行。

`benchmark/review.rb` 执行真实建议、命令和计划序列化，以捕获发布正文的目标替代文件写入；报告目录初始化在计时外，不包含网络/fsync。计时后逐项核对模板身份、完整配置指纹、命令与回退。macOS arm64 / Ruby 4.0.6，基线与候选各两个独立进程，每进程三个样本取中位数；区间是两次结果范围。

复测：`bundle exec ruby -Ilib benchmark/review.rb`；基线用 `-I/path/to/baseline/lib`，脚本打印实际加载入口。对比时使用相同脚本、Ruby 与依赖，不覆盖工作区源码。

完整 `bundle exec rake` 通过：316 个示例无失败，91 文件 lint 无违规，离线示例与 CLI 帮助通过。实际私有临时目录回归核对多个计划的指纹、下一份报告更新指纹，以及部分/歧义配置不导出可执行计划。没有执行远程设备动作、CI 或发布。
